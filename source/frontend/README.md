# OpenITSM 前端

Vue 3 + TypeScript + Vite + Element Plus。Vue Router 管理导航；Vue 响应式状态保存内存会话；原生 fetch 统一处理请求。没有其他运行时 UI 依赖。工程配置参考 [Vite 官方指南](https://vite.dev/guide/)。

```powershell
cd source/frontend
npm ci
npm exec vue-tsc -- --noEmit
npm exec vite -- build
npm test
npm exec vite
```

默认开发地址为 http://localhost:5173，必须使用 localhost 保持 Origin 与后端 local 配置一致，默认代理后端 8080。目标地址集中在 `BackendConfig.ts`；需要换端口时，在启动 Vite 的进程设置 `OPENITSM_BACKEND_URL`，不要修改 `.env`。实际运行端口以启动输出为准。

Vite 将 `/api` 同源代理到后端，保留浏览器 Origin 和 Cookie。不手动设置浏览器禁止脚本设置的 Origin 请求头，不使用跨站 Cookie，也不需要放宽后端 CORS。生产需由同源反向代理转发 `/api`，并对页面路径配置 SPA history fallback；本次未修改生产部署。

## 设计与代码

- [设计说明](./M01-design.md)：路由、页面、接口、错误处理四张表及差异。
- [验证记录](./verification/RESULTS.md)：实际执行结果与未联调项。
- `src/views/`：AuthPage（四条认证路由）、MembersPage、CreateTicketPage、TicketsPage、TicketDetailPage、PlaceholderPage。
- `src/components/`：品牌、统一错误展示、应用导航壳。
- `src/api/HttpClient.ts`：Cookie、CSRF、错误解析、幂等处理中的有限重试和限流截止时间。
- `src/stores/SessionStore.ts`：会话恢复、实际交互跟踪、60 秒心跳和 401 清理。
- `src/router/`：history 路由、认证守卫；应用壳在页内处理角色不足。
- `src/utils/Policy.ts`：Unicode 密码规则、角色权限、锁定状态。
- `tests/`：Node 自带测试运行器，覆盖密码、权限、锁定、CSRF、幂等头、错误原文、401 与 Retry-After。

邀请 API 没有 If-Match，按 API.md 仅附 Idempotency-Key。其余成员写请求使用列表 version，格式为带引号的 If-Match。一次操作保留请求快照，网络失败/503/处理中的手动重试复用原始内容和键。409 版本冲突只刷新列表，由用户重新打开并确认操作。

会话、CSRF、密码与邮件 token 均不持久化到 localStorage/sessionStorage。邮件链接为 `/activate?token=…`、`/reset-password?token=…`。页面使用 no-referrer，避免 token 通过引用来源头传播；不加载远程图片、字体或分析脚本。

本地数据库不提供默认前端登录账号。联调测试账号仅在隔离 Testcontainers 数据库中由测试初始化，不可当作本地业务库凭据使用。正常账号由既有后端 bootstrap 或管理员邀请建立。

## M02 提单

三角色均可从导航进入 `/tickets/new`。标题、描述、业务类型、影响范围为必填自由文本，调用 `POST /api/v1/tickets`，只附幂等键，不带 If-Match；成功展示真实编号与 ID，可进入详情。“继续提单”清空内容并开始新操作。网络/服务异常导致结果不确定时，保留原内容与幂等键并锁定表单，使用“重试提交”确认原请求；未增加本地持久化。

页面沿用既有桌面布局（最小宽度 1100px）。本次浏览器验收使用临时 5174/18083 端口及隔离数据库，后端 Origin 同步设置为 `http://localhost:5174`；正常开发仍按上述默认端口启动。验收结果见 [验证记录](./verification/RESULTS.md)。

## M05 列表、详情与检索

`/tickets` 提供我的工单；工程师和管理员另有我的待办、未分派、全部工单。对接真实 GET 接口，固定每页 20 条，状态、业务类型、关键词可组合筛选，查询条件与页码保留在 URL。`/tickets/:id` 显示真实工单信息和公开解决摘要，文本按普通文本渲染。失败可重试，空列表显示空状态。

SLA 已由 M07 接入；M04 沟通、附件与操作记录见下文。M05 浏览器验收使用临时 5175/18085 及隔离数据库，未改变默认开发配置。

## M03 工单操作

详情页的 `TicketActions.vue` 对接九个既有流转接口。`TicketPolicy.ts` 依据角色、负责人、状态和重开期限控制入口，最终权限由后端校验。分派/转派读取现有工程师候选及负载，原因和公开解决摘要按接口要求校验。

提交携带当前版本和独立幂等键；结果不确定时保留原正文、版本及键，锁定表单并提供“重试原操作”。版本或状态冲突显示后端提示、刷新详情，由用户重新确认操作。M03 浏览器验收使用临时 5176/18086 和隔离数据库；默认开发端口不变。

## M04 沟通与操作记录

详情页 `TicketCommunication.vue` 接入真实公开回复、内部备注和操作记录。员工只可公开回复本人提单，工程师、管理员可切换内部备注；内部项和员工不可见的操作原因由后端过滤。正文、原因与解决摘要按普通文本显示，不执行 HTML。沟通与操作记录各自每页 20 条、按时间升序，可分别刷新、翻页；读失败有独立重试入口。

发表须填写非空内容；沿用 Cookie/CSRF、工单版本及幂等键。成功刷新工单及记录并显示最新页；结果不确定时锁定内容与发表方式，重试原请求。版本/状态冲突显示原始错误并刷新详情，保留正文，由用户重新确认；与 M03 操作互相禁用。已解决仍可回复，关闭后隐藏编辑区，提示新建工单。

沟通与记录阶段使用临时 5177/18087 和 Testcontainers 隔离 PostgreSQL，未修改默认开发配置；实际结果及截图见 [验证记录](./verification/RESULTS.md)。SLA 见 M07。

## M04 附件

`TicketAttachments.vue` 提供附件上传、固定每页 20 条列表及鉴权下载。一次上传一个非空文件，最大 10 MiB（10485760 字节），不限制扩展名，不在线预览。员工仅能上传公开附件，工程师、管理员可选内部；内部附件及其操作对员工不可见。NEW/IN_PROGRESS/ON_HOLD/RESOLVED 可上传，关闭后隐藏上传区，已有附件仍可下载。

HttpClient 复用 Cookie/CSRF 和错误处理，FormData 由浏览器生成 multipart boundary，下载成功读取 Blob，错误继续解析统一 JSON。上传失败且结果不确定时锁定文件及可见性，重试保留原版本、文件和幂等键；冲突保留文件与后端错误并刷新详情，等待用户确认。上传、回复和工单流转提交互相禁用。

附件阶段浏览器验收使用 5178/18088、隔离 PostgreSQL 和后端 target/m04-browser-storage；不修改默认开发配置，不使用业务库或真实邮件。默认服务目录与存储配置见后端 README。

## M07 处理时限

列表和详情复用 GET 工单接口返回的真实 SLA。列表分别标识响应、解决的超时/达标/计时中；详情展示本轮目标及实际时间，统一按 Asia/Shanghai 显示。状态以最近加载为准；详情可手动刷新，操作成功也会刷新，刷新与写操作互斥。历史数据不足时明确显示，不用空值冒充达标。重开清空本轮时间，调整优先级后重新判定，包括已完成指标。

## M08 文本知识库

知识库导航已接入真实接口。工程师在“我的知识”创建、编辑本人草稿；管理员在“知识管理”发布或下架；全部角色在“已发布知识”按标题/正文和分类搜索、分页、阅读。正文按纯文本展示。下架回草稿；发布状态不可直接修改。写入复用现有 CSRF、版本、幂等和错误组件，结果不确定时保留原请求重试，冲突时保留编辑内容并刷新最新详情。

使用 `npm exec vue-tsc -- --noEmit`、`npm test`、`npm exec vite -- build` 验证。实际浏览器验收结果见 [验证记录](./verification/RESULTS.md)。


## M01～M08 补齐页面

新增个人资料/改密（/profile）、业务类型（/ticket-types）和管理员简单统计（/dashboard）；提单页接入统一类型、初始优先级、可选负责人及创建后独立附件重试。列表支持创建日期、类型、人员、优先级及待办结束范围；拒绝详情只读。知识详情增加随文章权限的附件上传、下载及草稿移除，单文件最大 100 MiB，工单仍为 10 MiB。

文件与未知结果的请求快照仅当前页面保留，刷新不承诺恢复；大文件传输等待上限 120 秒。创建成功后附件失败只重试附件，不重新建单。类型、状态和权限发生变化时服务端再次校验。AI 推荐与动态 SMTP 仍依赖后续模块，界面不提供占位成功结果。

本轮类型检查、构建及 19 项前端测试通过；后台数据库连接受阻，尚未完成实际页面联调及截图验收，详见根 STATUS。


## M14 团队配置

管理员 `/settings` 已接入真实 GET/PATCH 设置和模型连接测试，复用会话、Origin、CSRF、版本/幂等快照及错误展示。密码/密钥只显示配置状态，空输入保留原值，勾选清除才提交 clear 标志；结果不确定保留原请求重试。保存不触发连接测试、邮件投递或隐式开启 AI。

测试只使用已保存连接及固定文本，未保存修改时禁用测试入口。旧测试结果标明对应版本，版本冲突保留当前输入并允许重新读取。模型测试 429 仅冷却测试按钮，不进入全局人工操作冷却；失败、未测试和暂无业务调用明确区分。M09～M12 业务入口仍未开发。

本机验收使用 5189 临时前端和隔离后端，避免影响用户已有 5173 服务。最新类型检查、构建、20 项测试及浏览器结果见 verification/RESULTS.md 与根 STATUS。
